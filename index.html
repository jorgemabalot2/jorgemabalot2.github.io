Lost-client win-back engine

Cleaning company
Problem
Cancelled clients left with no follow-up, and the reason they left never reached the CRM.
Build
Cancellation emails route through Zapier's Email Parser, one mailbox per reason code. Reason tags in GoHighLevel start one of nine drip sequences, and a separate branch covers clients who signed up but never started service.
Result
A 15-page Win-Back Playbook approved by the CEO, plus a guardrail workflow for contacts that arrive without a reason code.

Vendor referral automation

Cleaning company
Problem
Clients needing out-of-scope services, such as pest control, were referred to 60+ partner vendors with no record and no credit to the vendor.
Build
A form that sales fills in live on the call, which triggers an automatic email to the vendor. I tested a custom-object design first, found platform limits, and rebuilt it as a contact-based workflow.

How I work

Four rules I build by

if/else

Guard before acting

Every workflow checks its data before it sends, tags, or moves anything. I plan for the edge cases before they happen.

one source

Meet the team where they work

Automations point staff to the system they already use every day, so no one needs to learn a new tool.

no guessing

Use the real number or leave it blank

Reports use the source value exactly. When data is missing, I say so rather than fill in an estimate.

docs

Leave a playbook behind

Systems ship with run sheets, FAQs, and playbooks, so they keep running when I'm not in the room.
